# ADR 0005: การรองรับการลงทะเบียนกิจกรรมพร้อมแนบลิงก์ Portfolio (a-Port)

## สถานะ (Status)
Accepted (เห็นชอบร่วมกันใน Grilling Session วันที่ 12 พฤศจิกายน 2569)

## บริบท (Context)
ในการจัดกิจกรรม Roadshow เช่น มจธ.ราชบุรี มดออนทัวร์ มีกิจกรรมประเภท Workshop หรือ Registration Activity ที่ต้องการให้นักเรียนส่งแฟ้มสะสมผลงาน (Portfolio / a-Port) ล่วงหน้าผ่านทางลิงก์ (เช่น Google Drive, Canva, Notion) เพื่อให้คณะกรรมการสามารถตรวจสอบและประเมินผลงานก่อนเริ่มกิจกรรม

เดิมทีตาราง `RegisterActivities` บันทึกเพียง `studentId`, `activityId` และ `registered_at` โดยไม่มีช่องทางสำหรับจัดเก็บลิงก์ผลงาน และระบบไม่มีการเปิด-ปิดฟังก์ชันนี้เป็นรายกิจกรรม ส่งผลให้ผู้ดูแลระบบไม่สามารถคัดกรองหรือตรวจสอบผลงานของผู้ลงทะเบียนได้โดยตรงผ่านระบบ

## การตัดสินใจ (Decision)

1. **การควบคุมในระดับกิจกรรม (Activity-Level Flag)**:
   - เพิ่มฟิลด์ `require_portfolio Boolean @default(false)` ในโมเดล `Activities`
   - ผู้ดูแลระบบ (Admin) สามารถเลือกเปิด-ปิดฟังก์ชันนี้ได้อิสระขณะสร้างหรือแก้ไขกิจกรรมผ่านหน้า [`AddActivityPage`](../../src/views/pages/_km/activities/AddActivityPage.tsx) และ [`ViewActivityPage`](../../src/views/pages/_km/activities/ViewActivityPage.tsx)

2. **การจัดเก็บข้อมูลการลงทะเบียน (Registration Data Model)**:
   - เพิ่มฟิลด์ `portfolio_url String? @db.VarChar(2048)` ในโมเดล `RegisterActivities` เพื่อรองรับ URL ที่มีความยาวสูง
   - ความเข้ากันได้แบบย้อนหลัง (Backward Compatibility): เป็นฟิลด์แบบ Nullable ทำให้กิจกรรมเดิมและกิจกรรมที่ไม่เปิดรับพอร์ตยังคงทำงานได้ตามปกติ 100%

3. **ประสบการณ์ผู้ใช้และหน้าจอแบบฟอร์ม (Student UX & Clean Interface)**:
   - สำหรับกิจกรรมที่เปิดรับพอร์ต เมื่อนักเรียนกดปุ่ม "ลงทะเบียนกิจกรรม" ในหน้า [`ViewActivityByID`](../../src/views/pages/app/ViewActivityByID.tsx) ระบบจะเปิด Modal ที่ออกแบบด้วย Chakra UI มาตรฐานอย่างเรียบง่าย
   - ไม่ใช้โครงสร้างเลเยอร์ DOM ซ้ำซ้อน (No AI Slop / No redundant wrapper divs)
   - มีข้อความกำกับสั้นกระชับ: `"โปรดตั้งค่าลิงก์เป็นสาธารณะ (Public)"` โดยไม่ใส่คำอธิบายซ้ำซ้อน
   - นักเรียนสามารถกดปุ่ม "แก้ไขลิงก์" ได้ในภายหลัง โดยระบบจะอัปเดต URL เดิมโดยไม่ตัดสิทธิ์การจองที่นั่งในกิจกรรม

4. **นโยบายการตรวจสอบข้อมูล (Validation Policy)**:
   - ไม่บังคับใช้ RegEx หรือจำกัดโดเมนเฉพาะ (No restrictive URL pattern check) เพื่อความยืดหยุ่นสูงสุดในการส่งลิงก์จากผู้ให้บริการต่าง ๆ
   - ระบบจะทำเพียงการตัดช่องว่าง (trim) ก่อนบันทึก

5. **การแสดงผลและการนำออกข้อมูลฝั่ง Admin (Admin View & Export)**:
   - ในหน้า [`ViewActivityPage`](../../src/views/pages/_km/activities/ViewActivityPage.tsx) แท็บ "รายชื่อผู้ลงทะเบียน":
     - แสดงคอลัมน์กระชับตามชื่อที่กำหนด: `ชื่อ-สกุล`, `อีเมล`, `เบอร์โทร`, `ลิงก์พอร์ต`, `เวลาลงทะเบียน`
     - มีปุ่มเปิดลิงก์ผลงานไปยังแท็บใหม่ทันที (`target="_blank"`)
   - ปุ่ม Export Excel: เพิ่มคอลัมน์ `ลิงก์พอร์ต` ลงในไฟล์ `.xlsx`

## ผลกระทบ (Consequences)
- **เชิงบวก (Positive)**:
  - ตอบโจทย์งาน Workshop ของ มจธ.ราชบุรี และคณะต่าง ๆ ในการรวบรวมพอร์ตโฟลิโอได้อย่างเป็นระบบ
  - Admin สามารถตรวจสอบและดาวน์โหลดรายชื่อพร้อมลิงก์ผลงานได้ทันทีผ่าน Back Office
  - โครงสร้างฐานข้อมูลสะอาด ไม่กระทบต่อกิจกรรมและระบบ E-Stamp เดิม
- **ข้อพึงระวัง (Considerations)**:
  - ต้องรัน Database Migration เพื่อเพิ่มคอลัมน์ในตาราง `Activities` และ `RegisterActivities` ในสภาพแวดล้อมจริง
